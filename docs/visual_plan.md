# 画面表现优化：现状、可行性评估与路线

分支 `visual`（从 `main` 拉出）。本文是研究结论 + 一批**粗糙原型**的记录；原型代码在 `game/tools/look_lab*`、`game/tools/ui_proto.*`，对比图在 `docs/visual/`。
原型都只在测试工具里，**没有接入游戏**。

## 一、现状（均已在仓库中核实）

| 项 | 现状 |
|---|---|
| 渲染 | `gl_compatibility`（OpenGL）；视口 940×590，`canvas_items` 拉伸；无抗锯齿设置、无 mipmap、默认线性过滤 |
| 角色 / 特效 | 原版矢量形状，用 FFDec `-zoom 2` 光栅化成部件贴图（悟空 165 张、共 177 个 rig），骨骼动画（AnimationPlayer 逐帧 key）|
| 场景 | 原版位图（多数 1× 的 jpg/png，如地面砖 474×98 一块），按 1×~2× 摆放；远景是单张图，没有分层视差 |
| UI | 原版整块位图 + 提取出来的文字框位置（45 个界面布局，约 1400 行界面代码）；近期的活动面板是原生控件 |
| 光影 | 没有光源、没有环境色、没有后期；只有每精灵的辉光 / 色彩矩阵着色器（`sprite_fx`）|
| 资源体积 | `game/assets` 约 290 MB（rig 127 MB、关卡 63 MB）|

看得出来的问题：画面偏平、前后景没有层次；地面砖里**烘焙了“4399”水印**；个别背景有细缝线（上面对比图里 x≈365 处的竖线）；全屏放大时 1× 位图发糊；人物与场景的明暗不统一；UI 文字要靠逐字段拟合才能对准底图。

## 二、几个问题的结论

### 1. 角色重绘：不建议，我也做不好
- 我没有图像生成能力。能做的只有手写 SVG / 程序化绘制。一个英雄要 165 个部件，加装备、时装、3 个英雄、52 个怪物，再保证几十个动作里每个部件都对得上 —— 数量上是几千张图，风格上也无法和场景的手绘质感统一，结果大概率比原版差。
- 管线上换图本身不难（部件按 key 取贴图，替换一批 PNG 即可），**瓶颈是美术来源**。如果以后有外部素材（画师 / 授权素材），可以走“换皮”管线。
- **低成本、有效的替代**：矢量部件可以用更高的 `-zoom`（3 或 4）重新光栅化，人物和特效在大屏 / 全屏更锐利。代价：贴图内存 ×2.25~4，导出包变大；位图类的场景素材不受益。建议只对英雄和主要 boss 试。

### 2. UI 重做：可行，性价比最高的一项（原型见 `docs/visual/ui_proto.png`）
- Godot 的 `StyleBoxFlat`（圆角、描边、阴影）+ Theme + 少量着色器就能做出干净的血条 / 提示框 / 菜单按钮；原型三件（HUD 条、物品提示、使用菜单）合计约 150 行代码。
- 好处：分辨率无关（不再受 2× 位图限制）、文字不用再逐字段对位（这一直是返工最多的地方）、改文案和多语言容易、状态（禁用 / 悬停 / 按下）统一。
- 代价与风险：风格会从原版水墨笔触变成“深色半透明 + 金边”的现代风；约 45 个界面，逐个重做是几周量级的工作，建议分批：①HUD ②提示 / 菜单 / 对话框 ③背包 / 强化 / 商店 ④地图 / 存档 / 结算。原版插画（人物头像、图标、标题字）可继续作为装饰素材。
- 效果判断：比原版的位图界面**更干净但少了手绘味道**；要有味道，需要给边框加纹理（9-slice 的纹理 StyleBox 可以复用原版的边框切片）。

### 3. 光影与质感着色器：可行，效果明显（原型见 `docs/visual/lighting_*.png`、`effects_sheet.png`、`outline_light.png`）
在 Compatibility 渲染器下已验证可用的做法：

| 手法 | 做法 | 观感 | 成本 / 风险 |
|---|---|---|---|
| 环境色 + 点光源 | `CanvasModulate` 压暗，`PointLight2D` 挂在英雄、技能弹道、场景灯火上 | 最明显：氛围、聚焦、技能有“照亮周围”的感觉 | 低；需要给光源设 `range_item_cull_mask`，免得英雄被自己的光晒白（原型里英雄略过曝）|
| 法线贴图（生成） | 画素着色器里用自身亮度 + 轮廓 alpha 的 Sobel 生成 `NORMAL_MAP`，让 2D 光源产生体积感 | 砖墙、盔甲有起伏；轻微，调强会脏 | 中：要给所有精灵加材质（可按层筛选）；和现有 `sprite_fx` 材质要合并 |
| 屏幕分级 + 暗角 | 全屏 `hint_screen_texture` 着色器：对比度 / 饱和度 / 分离色调 / 暗角 | 一次到位地统一画面，成本最低 | 极低；可每关一套参数 |
| 辉光（Bloom） | `WorldEnvironment` 的 glow（Compatibility 下可用）| 月亮、火焰、技能更亮；强度有限 | 低；效果受限于 LDR，需要 2D HDR 才更明显 |
| 角色轮廓 | 复用现有“镜像 rig + 单色轮廓”（`Rig.mirror`）做 2 px 深色描边 | 人物从背景里跳出来，可读性好 | 中：每个角色多一份 rig，要每帧同步；怪多时要测性能 |
| 氛围粒子 | `CPUParticles2D` 的雾、尘、萤火、飘叶，按关卡配 | 前景层次、空气感 | 低 |

粗糙之处（原型没调）：点光源强度和高度、法线强度、辉光阈值都是随手值；轮廓没有跟随怪物的状态更新；没测多怪物同屏的帧率。

### 4. 我想到的其他提升项（按性价比排序）
1. **去水印、修缝**：地面砖贴图里的“4399”字样和背景细缝线，用现成的 `tools/rig/fix_seams.js` 思路批处理即可，立竿见影。
2. **抗锯齿 / 过滤**：给精灵开 mipmap + 线性过滤，打开 2D MSAA，人物缩放和镜头移动时的闪烁和锯齿会少很多。
3. **分层视差**：现在远景只有一张图；多数场景的前景装饰其实已是独立精灵，可以按深度分 2~3 层给不同滚动速度。
4. **接触阴影 / 地面反光**：脚下的椭圆软阴影（已有影子的 boss 之外，其他角色补上）。
5. **打击感**：受击白闪（shader 一行）、短暂顿帧、镜头轻微缩放，成本低。
6. **整数缩放 / 分辨率**：窗口不是整数倍时位图会糊，可以提供“整数缩放”选项。
7. **技能特效**：给弹道和技能加光源和拖尾，是光影方案里观感最强的一块。

## 三、建议路线（每步都可以单独合入主分支，不改玩法）

| 阶段 | 内容 | 预期 |
|---|---|---|
| V1（小）**已做** | 去水印（`tools/rig/remove_watermark.js`，模板匹配 + 同图补丁覆盖，去掉了 1-1/1-3/2-1 场景和 1-x 地面砖的 4399）、受击白闪（`Rig.flash`，怪白 / 英雄红）。MSAA 实测对当前画面没有任何像素差异（Compatibility 下 2D MSAA 不起作用），mipmap 在当前缩放范围里也没有收益，两项没做 | 几乎无风险，先拿“干净” |
| V2（中） | 屏幕分级 + 暗角 + 辉光，按关卡配参数；氛围粒子 | 画面统一、有氛围；每关 5~10 个参数 |
| V3（中） | 环境光 + 点光源（英雄 / 弹道 / 灯火）+ 轮廓；法线强度做成可调 | 立体感，技能有光；需要性能与可读性测试 |
| V4（大） | UI 原生化，分四批 | 清晰、可缩放，风格要你拍板 |
| V5（可选） | 高 `-zoom` 重光栅化英雄 / boss；分层视差 | 大屏更锐利；包体增大 |

**不建议做**：手写 SVG 重绘角色；全局法线贴图手绘；把渲染器换成 Forward+（Compatibility 对老机器更友好，目前这些效果都够用）。

# 二、第二轮（2026-10-12）：墨笔 UI 方案、光影重新设计、V1 结果

## A. 用“其他技术栈”生成毛笔水墨质感 UI（已验证可行）
**做法**：Node 脚本 `tools/ui_ink/build.js` 把 SVG 图形交给本机的 Chrome / Edge（无头模式、透明背景、2× 分辨率）渲染成 PNG，不需要装任何 npm 包。质感全部来自 SVG 滤镜的参数：
- `feTurbulence`（分形噪声）+ `feDisplacementMap`：把边缘扰成撕裂的毛笔边，低频噪声管“走形”，高频噪声管“毛边”；
- 沿 x 方向拉长的噪声 + 阈值：切出**飞白**（干笔划痕）；
- 低频噪声叠加：墨色深浅不均的水墨洇染；
- 圆点散布：飞溅的墨点；
- 金线：带轻微扰动的细金边。
改一个数字重跑即可得到新的图（这是“参数化”的核心）。产物是 9 宫格面板、金色按钮四态（正常 / 悬停 / 按下 / 禁用）、HUD 墨牌、血条 / 蓝条 / 经验条、标题笔触、提示框，连同 `ink.json`（9 宫格边距）输出到 `game/assets/ui_ink/`；游戏里用 `NinePatchRect` / `TextureProgressBar` 直接用（`game/tools/ui_ink_proto.gd`）。
**效果**：见 `docs/visual/ui_ink_proto.png`——比纯原生控件版（`ui_proto.png`）接近原版的水墨感很多：撕裂墨边、飞白按钮、金线框。仍然不如原画师手绘的细节（笔触的粗细变化、墨团形状），但完全由参数控制、可批量出图、不受分辨率限制。
**还能怎么加强**（按性价比）：①笔锋：用沿路径变宽的描边（SVG 里用多段不同宽度的 path 叠加）做标题和分隔线；②宣纸 / 绢布底纹：给面板内部叠一张低对比的纸纤维噪声；③朱砂印章（红色方章 + 篆体字）做强调按钮；④纹样（云纹、回纹）用 SVG path 描成金线装饰；⑤原版素材里的边框切片可以混用。
**其他可选技术栈**（没有试，供比较）：Paper.js / Rough.js（线条手绘感）、p5.js / Canvas 的粒子笔刷（可做真正有笔压的笔触，需要无头浏览器跑）、Python 的 Pillow + numpy 噪声。结论：Chrome + SVG 滤镜已经够用且零依赖。

## B. 光影：为什么上一版“差点意思”，重新设计
上一版的问题：光是“每个角色背后一个亮点 + 全屏压暗”，光源和场景没有关系，没有层次，也没有“光从哪里来”的叙事。
**设计原则**
1. **光从场景里来**：每个关卡先做一份“光源清单”——从美术里认出能发光的东西：灯笼、火盆、月亮、符文、门缝、岩浆、水面反光，写成数据（位置、颜色、半径、强度、闪烁曲线）。角色不带光，只被这些光照亮；靠近火盆会被染橙，且受光的那一侧更亮。
2. **三层光**：主光（光源方向的暖光）、补光（偏冷的环境色，保证暗部不死黑）、轮廓光（从背景光源来的边缘光，让人物从背景里分离）。
3. **自发光要真的“亮”**：火焰、灯笼、符文、技能特效用加色混合 + 辉光，周围有光晕和地面光斑，而不是只靠整体调色。
4. **景深**：现在远景只有一张图；按距离给雾层和色调：远处偏冷偏灰、近处饱和，前景加虚化的暗角物体（柱子、铁链、枝叶）轻微视差。
5. **空气感**：光柱（体积光，加色渐变多边形 + 缓慢漂移）、飘动的粒子（火星、灰烬、萤火、雾），按关卡定制，不是一刀切。
6. **每关一份色彩脚本**：如 1 章“冷月 + 青灰雾 + 暖灯点缀”，2-3 阎罗殿“暗红 + 火盆暖光 + 冷色阴影”，忘川“幽蓝水光 + 白雾”，螺旋地狱“洋红 + 烟紫”。统一用“暗部偏冷、亮部偏暖”的分离色调（上一轮已验证有效）。
7. **动态响应**：技能 / 弹道 / 受击带短时光源（火球照亮四周、雷击闪屏），boss 大招有全屏色彩脉冲；英雄变身（怒气）时环境色轻微偏移。
8. **可读性优先**：光影绝不能盖掉判定可读性——地面、攻击预警、血条不受压暗影响（用独立 CanvasLayer / 光照遮罩层级）。

**本轮原型**（`docs/visual/designed_hall.png`，2-3 阎罗殿，左原样右新方案）：只用了 Godot 自带的 `PointLight2D` + 生成法线 + 加色精灵 + 粒子，做出了“火盆在发光、门后透红、地面有光斑、英雄靠火的一侧偏橙、暗部偏蓝”。仍然粗糙：光源位置是我读图估的、没有闪烁、没有光柱、前景层缺失、英雄的轮廓光没做。
**落地方式（建议）**：新增一个关卡数据文件（如 `game/data/lighting/sl23.json`：环境色、光源列表、光柱、雾层、粒子）+ 一个 `StageLighting` 节点在 `Level._ready` 里读取并创建节点；光源清单由我对着每关美术截图去标，你审核。这样“设计感”变成了数据，可以逐关迭代，且不会碰玩法代码。工作量：每关半小时到一小时（标光源 + 调参），20 余关。

## C. V1 结果
- **去水印**（已做）：`tools/rig/remove_watermark.js`。用 1-1 场景里的“4399”做模板，在所有关卡贴图上做多尺度归一化互相关匹配，找到 11 处（1-1 四处含两处被遮挡的半截、1-3 一处、2-1 四处、1-x 通用地面砖一处），用**同一张图里边缘最相似的补丁**覆盖（地面砖是左右循环的，补丁允许绕回）。看过 1-1 / 2-1 的前后对比，字已消失，补丁不显眼。2-2、2-3、3-x 等其它关用相同阈值没有找到匹配；我对这几关没有逐屏用眼睛检查，可能还有漏网的（工具支持手动补坐标）。
- **受击白闪**（已做）：`Rig.flash`——怪物白闪、英雄红闪，约 0.1 秒渐隐；带自己特效材质的部件（辉光、模糊）不闪。
- **修缝**：`seam_check` 仍报告 sl23 左缘一条 26 px、sl31 / sl32 在 y≈403 处各一段；我对 sl32 的对应位置截图看了，没有肉眼可见的缝，所以没改。
- **mipmap / MSAA**：实测 MSAA 对画面没有任何像素差异（Compatibility 渲染器下 2D MSAA 不生效），mipmap 在当前缩放范围里也没有收益，两项都没做，也不建议做。
